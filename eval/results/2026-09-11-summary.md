## Observations

- Constrained decoding flipped exactly one case correct->incorrect->fixed direction: `s14` ("What's playing in the bedroom?"). base43 called `get_now_playing({"group_id":"bedroom"})` — an invented, invalid id; constrained43 called `get_now_playing({"group_id":"RINCON_BEDROOM01:3"})` — the schema-valid group id, and scored correct. This is the one case constrained decoding fixed.
- Constrained decoding broke 4 cases (`s08`, `s11`, `m02`, `m09`), all with the identical failure shape: same tool, same correct arg *keys*, but the wrong `group_id` value — every one substitutes `"RINCON_KITCHEN01:1"` for the correct `"RINCON_LIVING01:2"`. E.g. `m02` ("turn the living room down to 20%"): base43 calls `set_group_volume({"group_id":"RINCON_LIVING01:2","volume":20})` (correct); constrained43 calls `set_group_volume({"group_id":"RINCON_KITCHEN01:1","volume":20})` (wrong room). Same pattern for `s08`/`pause`, `s11`/`set_group_volume`, `m09`/`set_group_mute`.
- The eval's `llm-agent eval` CLI does not report a forced-token or model-step breakdown per case (that stat is only produced by the separate `tests/constrained.rs` fixture harness) — neither result file nor its log carries a forced-token share, so no percentage is reported here for base43/constrained43.
- Aggregate correctness dropped under constraining, both single-step (46.2% -> 38.5%) and multi-step (58.8% -> 47.1%), driven entirely by the kitchen-default substitution pattern above plus one fix (`s14`); net -3 cases (16 -> 13 correct of 30 scored).
- `m21` (no_mutation, "Turn off the garage speakers" — garage doesn't exist in the fixture household): both runs incorrectly made a mutating `pause` call rather than declining — base43 on `RINCON_GARAGE01` (an invented id matching neither a real player nor a valid enum value), constrained43 on `RINCON_KITCHEN01:1` (a schema-valid substitution of the same kind seen in the broken cases above). Constrained decoding forced a valid id but did not fix the underlying decision to mutate when it shouldn't.
- `m22` (any_play, "Play something"): both runs failed to make any `play_*` call with a valid `group_id` — base43 hit `max_steps` (7 steps, agent error); constrained43 ended after 1 step with `calls=[]`. Neither run satisfies `any_play`.
- The two French cases, `m25` ("Mets en pause la cuisine.") and `m26` (volume nudge in French): `m25` is correct in both runs (`get_households_and_groups_and_players`, then `pause({"group_id":"RINCON_KITCHEN01:1"})`). `m26` is incorrect in both, for the same reason each time — missing the required `adjust_group_volume({"group_id":"RINCON_LIVING01:2","volume_delta":10})` call after step 0.
- Timing on the clean (uncontaminated) portion of constrained43 is comparable to base43 case-by-case (e.g. `s02` 8.76 vs 4.48 tok/s, `m01` 2.21 vs 5.25 tok/s — noisy in both directions, no systematic constrained-decoding slowdown outside the contaminated window); the contaminated window (`m13`, `m20`-`m23`) shows decode throughput at 0.53-1.35 tok/s vs a 5.2-5.9 tok/s baseline immediately before and after, consistent with a concurrent GPU consumer overlapping that span rather than any effect of `--constrained` itself.
