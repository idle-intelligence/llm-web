# Reference inputs

Four fixed `(messages, tools)` pairs used to generate the byte-for-byte /
logit-for-logit ground truth in `../rendered/` and `../logits/`. See
`scripts/export_reference.py` and `scripts/make_inputs.py`.

- `01_no_tools.json` — system + user, no tools (`"tools": []`). Hand-written,
  not derived from `make_inputs.py`.
- `02_tools_single.json` — system + user "pause the kitchen", with the
  12-tool subset of the real Sonos MCP tool list
  (`fixtures/sonos/tools-12.json`).
- `03_tools_multiturn.json` — same 12 tools; user asks to pause the kitchen;
  assistant calls `get_households_and_groups_and_players` (an OpenAI-style
  `tool_calls` entry, matching how the model itself emits calls once
  decoded/re-encoded — see `docs/MODELS.md` §3 for the chat template's
  `'tool_calls' in message` branch); a `tool`-role message returns a small
  fake two-household/two-room JSON result (Kitchen, Living Room with ids) —
  fake because the Sonos MCP README/schemas don't document the real output
  shape of `get_households_and_groups_and_players`. The conversation ends
  there so the next generation is the assistant's follow-up turn (expected:
  a `pause` call on the Kitchen group id).
- `04_tools_all.json` — same messages as `02_tools_single.json`, but all 34
  Sonos MCP tools (`fixtures/sonos/tools.json`). Used only to measure
  34-tool prefill size; no logits are generated for it (would be
  multi-hundred-MB per input, not worth it just to check tool-count
  scaling) — see `scripts/export_reference.py --render-only`.

## Tool schemas: real, not placeholder

`02` and `03`'s `tools` arrays are generated by `scripts/make_inputs.py`
from `fixtures/sonos/tools-12.json` (and `04` from `fixtures/sonos/tools.json`),
the real Sonos MCP `tools/list` schemas (see `fixtures/sonos/README.md`).
Each MCP entry (`{"name", "description", "inputSchema"}`) is converted
verbatim, field-for-field, no edits, into the transformers/OpenAI
function-calling shape:

```json
{"type": "function", "function": {"name": ..., "description": ..., "parameters": <inputSchema>}}
```

This is the shape `export_reference.py` passes to
`tokenizer.apply_chat_template(..., tools=tools)`; per `docs/MODELS.md` the
template itself just `tojson`-dumps whatever object sits in each `tools[]`
entry (it doesn't unwrap the `type`/`function` wrapper), so this wrapped
shape appears verbatim inside the rendered prompt's system block.

An earlier version of `02`/`03` used 12 hand-written placeholder schemas
(invented descriptions, plausible but not real) because no `tools/list`
capture existed yet. That capture now exists
(`fixtures/sonos/tools.json`/`tools-12.json`, 2026-09-10) and the
placeholders are gone — regenerate `02`/`03`/`04` from the real schemas by
running `scripts/make_inputs.py` (never hand-edit their `tools` arrays).
