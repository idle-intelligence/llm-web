# lean engine, browser build (wasm32-unknown-unknown + WebGPU)

Engine milestone 1, browser half. Crate `crates/lean`, feature `web`
(wasm-bindgen surface `src/web.rs`). Native reference: `lean-cli` on the
same GGUF/tokenizer.

## Parameters

- Model: Qwen2.5-0.5B-Instruct, GGUF `qwen2.5-0.5b-instruct-q4_0.gguf`
  (Q4_0 weights, Q8_0 `output.weight`), tokenizer from
  `Qwen/Qwen2.5-0.5B-Instruct` (`tokenizer.json` + `tokenizer_config.json`).
- Config (read from GGUF metadata): 24 layers, hidden 896, 14 heads, 2 KV
  heads, head_dim 64, intermediate 4864, vocab 151936, rope_theta 1e6,
  rms_norm_eps 1e-6.
- Fixture: `crates/lean/reference/fixture.json` (HF transformers on the
  same GGUF, `reference/gen_fixture.py`), 3 cases (`short` 36 prompt
  tokens, `long` 86, `non_english` 54), 32-token greedy continuation each.
- Kernel path: `fast_kernels = true` (tiled Q4_0 prefill matmul, coalesced
  Q4_0 decode matvec, naive Q8_0 lm-head) on both native and browser.
- Native: macOS 26.3.1, Metal backend via wgpu 26.
- Browser: Playwright-bundled Chromium ("Google Chrome for Testing"
  153.0.8010.12), headless, launched with `--enable-unsafe-webgpu
  --enable-features=Vulkan,WebGPU --use-angle=metal`. Model served locally
  (`?local=1`) from a `python3 -m http.server` rooted at `crates/lean/`.
- wasm build: `wasm-pack build crates/lean --target web --no-default-features --features web`.
  Engine build tag in the harness page: `2026-09-28-2`.
  `lean_bg.wasm` sha256 `8345ede864c89857ce284ebedbe8dfb92412b6549798694d98536270d7f890ca`
  (3,303,655 bytes), `lean.js` sha256
  `c0c73ee8ca5588dc3a651e393a31ba47d3d707a02faa441ffa08e0ccc3483aef`.
- One GPU job at a time: native `lean-cli` run and the headless browser run
  were not run concurrently.

## Results

Native (`lean-cli --tokens 32 --kernel fast`):

| case        | prompt tokens | tokens match | top1 match | prefill ms/tok | decode ms/tok |
|-------------|--------------:|:------------:|:----------:|---------------:|--------------:|
| short       | 36            | true         | true       | 59.08           | 51.59         |
| long        | 86            | true         | true       | 38.38           | 52.33         |
| non_english | 54            | true         | true       | 39.98           | 51.97         |

Browser (headless Chromium, WebGPU, `?local=1`, harness page
`crates/lean/www/index.html`, `LeanEngine.generate(prompt, 32, on_token)`):

| case        | prompt tokens | tokens match | prefill ms | decode ms/tok |
|-------------|--------------:|:------------:|-----------:|--------------:|
| short       | 36            | true         | 400.4      | 26.6          |
| long        | 86            | true         | 457.1      | 27.2          |
| non_english | 54            | true         | 294.6      | 26.4          |

Device info reported by the browser run: `max_storage_buffer_binding_size
= 4294967292` (Metal via ANGLE reports the full ~4GB range, so
`quant.rs::chunk_rows` produces exactly one chunk for every weight in this
model - the general chunking code path is exercised, not idle, but never
triggers a second chunk for this model/adapter pair).

Native GPU load time: 321.06ms. Browser fetch (local files) + model load:
211ms fetch + 641ms GPU upload.

## Observations

- All three fixture prompts are token-exact between the browser build and
  the native/HF-transformers reference (`tokens_match = true` for all 3
  cases, both runs) - the browser generation text for each case:
  - short: "The capital of France is Paris. It is the largest city in
    Europe and the largest city in the world by population. Paris is a
    city with a rich history"
  - long: "Sure, here are the first fifteen elements of the periodic
    table, along with their atomic number, standard atomic weight, and
    one short fact about each element's most"
  - non_english: "La capitale de l'Allemagne, Berlin, est la capitale de
    l'Allemagne, et elle a été choisie pour plusieurs rais"
- Browser decode ms/token (26.6-26.9) came in faster than native decode
  ms/token (51.6-52.3) in this run. Both measurements used the same
  fast-kernel path on the same machine, one GPU job at a time; the
  browser side's per-token timing is JS `performance.now()` deltas between
  successive `on_token` callbacks (see `crates/lean/www/main.js`), not a
  Rust-side instrument, so the two numbers are not from identical
  instrumentation - flagged here rather than explained away. This needs a
  same-instrumentation re-measurement (e.g. a native harness using the
  same callback-gap methodology, or a browser build reporting Rust-side
  timestamps) before treating either number as the browser's true
  per-token cost.
- Browser prefill ms figures above are wall-clock ms for the whole prefill
  call (`genStart` to the first `on_token`), not divided by prompt length,
  unlike the native table's prefill ms/token - the two prefill columns are
  not directly comparable as printed; the native `long` case (86 tokens,
  38.38 ms/tok => ~3.3s total) versus the browser `long` case (457.1ms
  total for prefill) is the more relevant single-number comparison, and
  is the same "faster in the browser" pattern as decode.
- wasm binary size: 3.3MB (`lean_bg.wasm`), a fraction of `llm-wasm`'s
  ~15-20MB Burn+CubeCL build (see `tracker/projects/llm-web/engine-plan.md`'s
  "What exists today" note) - consistent with this crate's raw-wgpu,
  no-framework design.
- The Hugging Face default source URLs
  (`Qwen/Qwen2.5-0.5B-Instruct-GGUF/resolve/main/qwen2.5-0.5b-instruct-q4_0.gguf`,
  `Qwen/Qwen2.5-0.5B-Instruct/resolve/main/{tokenizer.json,tokenizer_config.json}`)
  were checked with `curl -I -L` and resolve (302/307 to the CDN); the
  default (non-`?local=1`) path was not run end-to-end in this session
  (bandwidth/time) - it exercises the identical `load()`/`generate()` code
  path already verified against local files, with only the fetch source
  differing.
- Native and wasm builds both pass from a fresh checkout:
  `cargo test -p lean --release` (2 unit tests, fixture_parity `#[ignore]`d
  without env vars), `cargo test -p lean --release -- --ignored
  fixture_parity` with `LEAN_GGUF`/`LEAN_TOKENIZER_DIR` set (passes,
  token-exact, both kernel paths), `cargo clippy -p lean --all-targets - -
  -D warnings` (clean), `cargo check`/`clippy -p lean --lib --target
  wasm32-unknown-unknown --no-default-features --features web` (both
  clean), `wasm-pack build crates/lean --target web --no-default-features
  --features web` (succeeds).
