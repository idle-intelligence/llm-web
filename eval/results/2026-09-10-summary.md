## Observations

- In the two `default` runs (a, b) the model invented a made-up group/player id (e.g. `"1234"`, `"the kitchen"`, `"Kitchen"`, `"Home"`, `"Bedroom"`) as its very first tool call in all 7/7 of the "quick action without a canonical id" cases (`s06`-`s09`, `m01`, `m04`, `m07`) combined across both runs (14/14 instances total). Example: for `s09` ("Resume playback."), run a called `resume({"group_id":"1234"})` directly and was scored incorrect.
- In the two `ids-from-tools` runs (c, d) the model called a `get_*` listing tool before the mutating call in 4/14 of those same 7 cases per run combined (10/14 still invented an id), e.g. for `s09` run c called `get_households_and_groups_and_players({})` first, then `resume({"group_id":"RINCON_LIVING01:2"})`, and was scored correct.
- `m01` ("Pause the kitchen.") flips from incorrect to correct only in run d: run a calls `get_group_volume({"group_id":"the kitchen"})` then `pause({"group_id":"the kitchen"})` (invented id, wrong), while run d calls `get_households_and_groups_and_players({})` then `pause({"group_id":"RINCON_KITCHEN01:1"})` (looked up, correct).
- `s02`, `m08` are correct in all 4 runs; `s01`, `s06`, `s07`, `s08`, `m04`, `m05`, `m09` are incorrect in all 4 runs regardless of system prompt or tool count.
- Mean decode throughput roughly halves under the 34-tool set versus the 12-tool set (5.87/5.50 tok/s at 12 tools vs. 2.95/2.87 tok/s at 34 tools) — the longer shared KV-cache prefix (up to ~8k tokens at 34 tools vs. ~2.2k at 12 tools) slows per-token decode, not just prefill.
- Overall correct% is not monotonic with the `ids-from-tools` instruction: it drops at 12 tools (26.7% -> 20.0%) but rises at all tools (25.0% -> 30.0%), and single-step vs. multi-step correct% move in opposite directions between run c and run d (28.6%/12.5% vs. 20.0%/40.0%).
