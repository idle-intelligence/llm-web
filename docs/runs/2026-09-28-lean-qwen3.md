# lean engine, Qwen3 native + browser follow-up

Follow-up to `2026-09-28-lean-web.md`, gated on `ad38939` (head_dim-general
attention: `attn_decode` takes HEAD_DIM as a WGSL pipeline-overridable
constant, pipelines built for 64 and 128 from one source; `attn_prefill`
and `attn_chunk_masked` size their private accumulator for up to 128 and
loop to the runtime head_dim). Native only in that commit: recording a
28-layer forward in one submit timed out in `device.poll` (60s wgpu-core
wait) even on short prompts, so `Engine::flush_encoder` now submits and
waits once per layer for native; the browser path is unchanged.

## Parameters

- Models: Qwen2.5-0.5B-Instruct (`qwen2.5-0.5b-instruct-q4_0.gguf`, 24
  layers, hidden 896, head_dim 64, vocab 151936) and Qwen3-0.6B
  (`Qwen3-0.6B-Q8_0.gguf`, 28 layers, hidden 1024, vocab 151936, head_dim
  128).
- Fixtures: `crates/lean/reference/fixture.json` (Qwen2.5, 5 cases incl.
  a 2225/2354-token tool-call prompt) and
  `crates/lean/reference/fixture_qwen3.json` (Qwen3-0.6B, 4 cases incl.
  a 2225-token agent prompt).
- Native: macOS 26.3.1, Metal backend via wgpu 26, `lean-cli` fast-kernel
  path.
- Browser: Playwright-bundled Chromium headless, launched with
  `--enable-unsafe-webgpu --enable-features=Vulkan,WebGPU
  --use-angle=metal`. Models served locally (`?local=1`) from
  `python3 -m http.server` rooted at `crates/lean/`.
- wasm build: `wasm-pack build crates/lean --target web
  --no-default-features --features web`. Engine build tag bumped to
  `2026-09-28-9` in `crates/lean/www/main.js` and
  `crates/lean/www/main_qwen3.js`; served `lean_bg.wasm` sha256
  `c1cbd38bee84bf6ecae39a44df071ecf07f19fa786a278bc3c27dd376ff80027`
  verified equal to the freshly built file before either browser run.
- One GPU job at a time: the two headless runs (Qwen2.5, then Qwen3) ran
  sequentially, no other GPU job concurrent.

## Observations

- Browser Qwen3-0.6B is token-exact against the reference on all 4
  fixture cases in the same run that verified the wasm-pack rebuild's
  served bytes match the build output, no shader-validation or
  override-constant divergence observed between native and browser for
  the head_dim=128 path.
- Qwen3 browser decode is slower per token than Qwen2.5 browser decode on
  the short/long/non_english cases (45.1-46.4 ms/tok vs 24.1-24.4 ms/tok)
  even though Qwen3-0.6B's hidden size (1024) and head_dim (128) are each
  larger than Qwen2.5-0.5B's (896, 64) by less than 2x; consistent
  direction with native's smaller head_dim-general-attention regression
  (52 to 63 ms/step) but not the same ratio, and the two are not
  controlled for kernel differences beyond head_dim (also more layers, 28
  vs 24).
- The `long_tools_single` case (2225 prompt tokens) is present in both
  fixtures and is markedly slower in the browser for Qwen3 than Qwen2.5
  at the same prompt length (38975.3 ms vs 17920.9 ms prefill; 170.9 vs
  155.8 ms/tok decode), same direction as the per-case comparisons above.
- Native's per-layer flush (`Engine::flush_encoder` submitting and
  waiting once per layer instead of once per forward pass) is a
  native-only change; the browser path still does a single submit per
  forward pass. This is the mechanism note for the native decode
  regression above, not a browser-observed effect.
- Time did not remain in this session for the Qwen3-1.7B download,
  reference-fixture generation, and native/browser gating (step 4 of the
  brief) after steps 1-3.
