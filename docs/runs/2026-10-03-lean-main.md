# 2026-10-03: lean-main, one engine branch

lean-main joins the two branches that grew out of lean-next (b63ff51) on
2026-10-03: the GPU prefill work (lean-prefill) and the CPU backend's
runtime LoRA (lean-cpu-lora). It also fixes the llm-web chat page's cache
check.

## What merged

| merge | branch head | what it brings |
|---|---|---|
| 94b7211 | lean-prefill 855d388 | small-M Q4_0/Q8_0 prefill kernel staging x in workgroup memory (652f98c), tiled prefill attention `attn_prefill_tiled.wgsl` (1a5c955), run log 2026-10-03-lean-prefill.md |
| cf97cdd | lean-cpu-lora 07f39a4 | CPU backend runtime LoRA (`CpuModel::apply_lora`), ForwardSpec chunk forward with caller positions and masks (`cpu::forward_chunk_spec`), `CpuModel::embed_head_sliced`, a multi-row CPU kernel, test `cpu_lora_parity.rs` |

Both merges are `--no-ff` and keep each branch's history. Neither had a
conflict: lean-prefill touches the GPU shaders, `model.rs` routing,
`engine.rs` and `www/`; lean-cpu-lora touches `cpu.rs`, `cpu_kernels.rs`,
`lora.rs` and adds one test. The one shared file in the engine is
`lora.rs`, changed only by lean-cpu-lora: the adapter factors are now built
once on the host (`HostLoraProj`) and the GPU uploads the same numbers the
CPU keeps, with no change to the GPU forward.

## Parameters

- M2 laptop, native Metal for the cargo gates; Playwright's bundled
  headless Chromium (`--enable-unsafe-webgpu --use-angle=metal`) for the
  browser, which reports adapter `apple / metal-3`.
- Models: Qwen2.5-0.5B-Instruct Q4_0 (default), Qwen2.5-3B-Instruct Q4_0,
  Qwen3-0.6B Q8_0, Qwen3-1.7B Q8_0, SmolLM2-360M-Instruct Q4_0/Q8_0,
  SmolLM2-1.7B-Instruct Q8_0. Adapters: llm-life's `a-rules-300`
  (lora_parity), `a-norules-300` (cpu_lora_parity); reference for
  cpu_lora_parity is llm-life's `hf_peft_reference.json`.

  greedy tokens, `?backend=` forced.
- wasm builds: `wasm-pack build crates/lean --target web --release
  --no-default-features --features web` and `scripts/build_lean_mt.sh`,
  both with `--remap-path-prefix` for the home directory.

## Observations

- Every gate passes on the merged tree: seven fixture parities, the CPU
  fixture with and without threads, the GPU and CPU LoRA parities, the
  kv_snapshot / logit_mask / pool_reuse / embed_head_sliced tests, lib
  tests and clippy on all three targets.
- llm-life's answers match HF+PEFT on every case on WebGPU and on the CPU
  backend (0 differ in every row). The adapter counts (512/512 a-norules,
  215/512 base with rules) equal the numbers in llm-life's lean-migration
  run log.
- All four browser runs produce the transformers token hash, on all three
  backends for Qwen and on WebGPU for SmolLM2-360M.
- Interleaved in one session, lean-main's 36-token prefill is 88.5 ms
  against lean-next's 109.7 ms, decode unchanged at 7.1 ms/token.
  lean-main and lean-prefill read the same (88.5 vs 88.5 / 86.9), as
  expected from identical GPU code.
- Absolute prefill on this session is higher than the earlier records for
  the same builds: lean-prefill's log has prefill-02 at 52.9 ms and
  next-era builds at 66-78 ms. The 5-minute load average here was 3.4-4.2
  while the 1-minute one was under 3. Compare the builds within one table,
  not across sessions.
